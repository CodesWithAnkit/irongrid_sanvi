# Production Environment Setup Guide

## Overview

This guide covers setting up environment variables for production deployment on Railway. The IronGrid backend requires specific configuration for security, performance, and integration with external services.

## Quick Setup

### Automated Setup (Recommended)
```bash
# Run the automated setup script
cd backend
chmod +x scripts/setup-production-env.sh
./scripts/setup-production-env.sh

# Or use PowerShell on Windows
.\scripts\setup-production-env.ps1
```

### Manual Setup
```bash
# Set core variables
railway variables set NODE_ENV=production
railway variables set PORT=3001

# Generate and set JWT secrets
railway variables set JWT_ACCESS_SECRET="$(openssl rand -base64 32)"
railway variables set JWT_REFRESH_SECRET="$(openssl rand -base64 32)"

# Set CORS and security
railway variables set ALLOWED_ORIGINS="https://your-frontend.vercel.app"
railway variables set COOKIE_SECURE=true
railway variables set SAME_SITE=none
```

## Required Environment Variables

### Application Core
```bash
NODE_ENV=production              # Application environment
PORT=3001                       # Application port
DATABASE_URL=                   # Auto-generated by Railway PostgreSQL
```

### Authentication & Security
```bash
JWT_ACCESS_SECRET=              # 32+ character secret for access tokens
JWT_REFRESH_SECRET=             # 32+ character secret for refresh tokens
```

### Network Configuration
```bash
ALLOWED_ORIGINS=                # Comma-separated CORS origins
COOKIE_DOMAIN=                  # Domain for secure cookies
COOKIE_SECURE=true              # Enable secure cookies
SAME_SITE=none                  # SameSite cookie attribute
```

## Optional Environment Variables

### Caching & Performance
```bash
REDIS_URL=                      # Auto-generated by Railway Redis
CACHE_TTL_DEFAULT=3600          # Default cache TTL (1 hour)
CACHE_TTL_SHORT=300             # Short cache TTL (5 minutes)
CACHE_TTL_LONG=7200             # Long cache TTL (2 hours)
ENABLE_CACHE_WARMING=true       # Enable cache warming
```

### Rate Limiting
```bash
RATE_LIMIT_WINDOW_MS=900000     # Rate limit window (15 minutes)
RATE_LIMIT_MAX_REQUESTS=100     # Max requests per window
```

### Monitoring & Logging
```bash
ENABLE_DB_METRICS=true          # Enable database metrics
LOG_SLOW_QUERIES=true           # Log slow database queries
SLOW_QUERY_THRESHOLD=1000       # Slow query threshold (1 second)
```

### Security Headers
```bash
ENABLE_HELMET=true              # Enable Helmet security headers
ENABLE_RATE_LIMITING=true       # Enable rate limiting middleware
```

### AWS S3 File Storage (Optional)
```bash
AWS_ACCESS_KEY_ID=              # AWS access key
AWS_SECRET_ACCESS_KEY=          # AWS secret key
AWS_REGION=us-east-1            # AWS region
AWS_S3_BUCKET=                  # S3 bucket name
```

### Email Service (Optional)
```bash
SENDGRID_API_KEY=               # SendGrid API key
FROM_EMAIL=                     # From email address
```

### Error Tracking (Optional)
```bash
SENTRY_DSN=                     # Sentry DSN for error tracking
```

## Environment Variable Generation

### JWT Secrets
Generate secure 32+ character secrets:

```bash
# Using OpenSSL
openssl rand -base64 32

# Using Node.js
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

# Using PowerShell
[Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

### Domain Configuration
Update these with your actual domains:

```bash
# Frontend domain (Vercel)
ALLOWED_ORIGINS=https://app.yourdomain.com,https://yourdomain.com

# Backend domain (Railway)
COOKIE_DOMAIN=api.yourdomain.com
```

## Security Best Practices

### Secret Management
- Use Railway's environment variables dashboard
- Never commit secrets to version control
- Rotate secrets regularly
- Use strong, unique secrets for each environment

### CORS Configuration
```bash
# Production domains only
ALLOWED_ORIGINS=https://app.yourdomain.com,https://yourdomain.com

# Avoid wildcards in production
# ALLOWED_ORIGINS=* # ❌ Never do this
```

### Cookie Security
```bash
# Secure cookies for HTTPS
COOKIE_SECURE=true

# SameSite for cross-origin requests
SAME_SITE=none

# Domain-specific cookies
COOKIE_DOMAIN=yourdomain.com
```

## Troubleshooting

### Common Issues

#### Missing Required Variables
```bash
# Check which variables are missing
npm run validate:env

# Set missing variables
railway variables set VARIABLE_NAME=value
```

#### Database Connection Issues
```bash
# Test database connectivity
npm run test:db

# Check Railway services
railway status
railway services
```

#### CORS Errors
```bash
# Update CORS origins
railway variables set ALLOWED_ORIGINS="https://your-actual-domain.com"

# Restart the service
railway restart
```

### Environment Variable Commands
```bash
# List all variables
railway variables

# Set a variable
railway variables set KEY=value

# Delete a variable
railway variables delete KEY

# View logs
railway logs --tail
```

## Deployment Checklist

Before deploying to production:

- [ ] All required environment variables are set
- [ ] JWT secrets are secure (32+ characters)
- [ ] CORS origins are configured for production domains
- [ ] Cookie settings are secure (HTTPS, SameSite)
- [ ] Rate limiting is enabled
- [ ] Database and Redis connections are tested
- [ ] Optional services (S3, SendGrid, Sentry) are configured if needed
- [ ] Environment validation passes
- [ ] Security headers are enabled
